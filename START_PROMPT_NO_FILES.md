# Portable one-prompt summary for Codex (when the full design pack is unavailable)

You are building M²D (Move · Motive · Decision), an independent, single-user, personal AI Investment Intelligence & Trading Decision System. Motto: "See the Move. Understand the Motive. Make the Decision." Build local-first Docker Compose software that can move unchanged to a private cloud host. User wants to improve risk-adjusted, after-cost investment returns with proactive portfolio monitoring, market/company research, options analysis, opportunities, exit plans and a measurable trading journal. Do not guarantee profits.

## Hard exclusions
Do NOT use OpenClaw or a generic prebuilt agent platform. Do NOT connect to IBKR/Questrade or any brokerage, collect broker credentials, sync brokerage accounts, execute orders, implement automated trading, signup, multi-user, tenant/RBAC, SaaS billing or subscriptions. Broker names are account labels only. External market-data, options, SEC/IR, news, FX and LLM APIs ARE allowed. Do NOT use ChatGPT sign-in, OAuth, session credentials or subscription-backed inference access.

## Core portfolio update contract
Single owner can create many manually tracked accounts with account types (cash, margin, RRSP, TFSA, etc.), stocks, ETFs, option contracts and multicurrency cash. Two write modes:
(1) natural-language incremental operations (stock/options trades, option open/close/expiry/assignment/exercise, dividends, cash adjustments, transfers, corrections) parsed by LLM into typed command; reject ambiguous data; deterministic preview exact before/after/cash; **human confirm** before one DB transaction commits event;
(2) uploaded complete Excel workbook replaces the entire current state of ALL accounts, positions and cash after validation+diff+confirmation. Missing old positions become zero, absent accounts deactivate. Preserve previous baselines/events/valuation snapshots; never silently merge, delete history, infer historic sales or calculate fabricated realized P&L. Subsequent NL changes apply on the latest baseline, previous events not reapplied. Use revision concurrency checks, idempotency keys, immutable audit changes and restore-as-new-baseline.

## Financial rules
Use PostgreSQL NUMERIC and decimal-safe arithmetic. Position qty signed, short calls/puts negative, option contract multiplier and deliverable explicit (100 is standard but not universal), native currencies and FX as-of. Short premium raises cash, short-option mark is a negative liability, not instantaneous profit. Covered vs uncovered option exposure, contract expiry/assignment scenarios, Greeks/delta exposure, realistic spread/fees/slippage, stress tests. For Excel avg cost baseline label pre-baseline realized P&L and performance as incomplete. NAV changes with deposits cannot be reported as investment returns. User trade fill vs AI signal vs simulated fill distinct.

## Market/research requirements
Provider interfaces for quotes (bid/ask/last, provider, timestamp/session/delay/freshness), OHLCV, options chain/Greeks/IV/OI, FX, financials, SEC filings/XBRL, news, uploaded reports. Store original raw source, published_at/available_at/observed_at and revisions; cite source/page and compare material changes. Historical backtests must not access future/revised data. Delayed/EOD quotes never masquerade as current pre/post-market or executable prices. Internet may fail, fixtures must work.

## AI and decisions
Custom bounded agent loop: classify intent -> gather portfolio/market/research context -> typed function calls -> deterministic finance validation -> answer/signal -> record evidence. LLM never writes DB or shell. Agent answers short, timestamped, source-grounded; if no valid trade, say NO_SIGNAL. Structured signal requires ticker/account, current quote/time/session, entry trigger, qty/risk budget, option legs if applicable, fees/slippage, stop/invalidation, targets, risk-reward where computable, main contrary thesis, evidence and expiry. Track DISCOVERED->QUALIFIED->ARMED->TRIGGERED->ACTIVE->CLOSED/INVALIDATED/EXPIRED. Evaluate signals prospectively with sample sizes, cost, slippage and out-of-sample results.

## LLM provider boundary
Initial configured provider is OpenAI through its direct API, with `OPENAI_API_KEY` loaded only from backend/worker environment variables. Use `LLM_PROVIDER=openai` and explicit `LLM_MODEL` for configured inference; `LLM_PROVIDER=fixture` is the offline CI/demo mode and requires no keys. Never expose secrets in frontend variables, responses or logs; `.env.example` contains placeholders only. Require the selected provider's credentials and reject invalid configuration instead of silently falling back.

Define provider-neutral `LlmProvider` contracts/factory/adapters in `packages/llm`; `packages/agent` owns orchestration, tool execution, history and per-run budgets. A `generate(request, signal?)` contract uses canonical items, declared model capabilities and normalized results/errors; normalize streaming events for the existing chat requirement. Preserve opaque provider/model/version-scoped continuation alongside canonical history so multi-step calls retain required provider state. Never replay one provider's continuation into another provider. Keep native SDK types inside adapters. Validate structured outputs and tool arguments before domain code runs; incomplete/refused responses are not valid trade decisions. Implement fixture and OpenAI adapters in M2; reserve Gemini and Anthropic Claude adapters for future work. No external orchestration framework. When the full pack is available, `docs/14_LLM_PROVIDERS.md` is the detailed contract.

## Autonomous work and UI
Offer Quick, Standard (default) and Extensive analysis beside chat/manual scan requests, with a saved single-workspace default. Modes alter evidence breadth, alternatives and bounded model/tool work, independently of provider/model. Enforce the same freshness, deterministic risk checks and confirmation in every mode. Keep all conclusions concise with expandable detail. Persist the selected mode on each job/run; no silent escalation, provider switch or budget increase. Define mode profiles beneath deployment ceilings, retaining 8 model attempts/120 seconds as Standard's initial policy, and report limited/unfinished coverage when a budget is exhausted. Implement the selector/policies in M2; later research tools retain their original milestones. In the full pack use `docs/15_ANALYSIS_MODES.md`.

Separate worker schedules portfolio and watchlist scans, option expiry checks, company filing/news updates, opportunity discovery in bounded liquid universe, daily brief, weekly review. Alert only on material new change; dedup. Show scheduler offline/missed-run status. Next.js UI: home portfolio dashboard, accounts/positions/cash, options & risks, price/volume charts and watchlists, opportunities, research/filings, journal/performance, AI chat. Enable bilingual user chat (Chinese/English) and readable previews.

## Stack and operations
Strict TypeScript pnpm monorepo; apps/web Next.js, apps/api Fastify, apps/worker; packages/domain/db/portfolio/market/ingestion/research/agent/llm/risk/strategy/monitoring/performance. PostgreSQL + Drizzle migration, pg-boss queues/jobs (no Redis), Zod route/tool contracts, decimal.js finance, Vitest tests, Playwright E2E, optional pgvector when needed. Docker Compose 4 services web/api/worker/postgres, persistent DB/uploads/research volumes, localhost-by-default, fixture mode without keys; later container deployment to private cloud. No microservices or enterprise security module.
